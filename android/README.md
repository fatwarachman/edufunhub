# EduFunHub Android (Google Play)

Trusted Web Activity (TWA) generated by Bubblewrap from `public/manifest.webmanifest`.
The app opens `https://edufunhub.com/dashboard?source=twa` full screen, without
the Chrome address bar, as long as Digital Asset Links verify.

- Package: `com.edufunhub.app`
- Host: `edufunhub.com` (production only; `dev.edufunhub.com` is not trusted)
- Version: `appVersionCode` / `appVersionName` in `app/build.gradle` and
  `twa-manifest.json`. Raise `versionCode` on every Play upload.

## Build

```bash
android/build.sh keystore      # once: upload key in /root/.edufunhub-android (600)
android/build.sh               # dist/edufunhub.aab (Play) + dist/edufunhub.apk (sideload)
android/build.sh fingerprint   # SHA-256 of the upload key
```

Back up `/root/.edufunhub-android/` somewhere safe. Losing the upload key means
a key reset request to Google Play.

## Digital Asset Links (hides the address bar)

Production `.env`:

```
ANDROID_PACKAGE_NAME=com.edufunhub.app
ANDROID_SHA256_CERT_FINGERPRINTS=<upload key SHA-256>,<Play App Signing SHA-256>
```

The Play App Signing SHA-256 appears in Play Console > Test and release >
App integrity after the first upload. Add it, redeploy, then check:

```bash
curl https://edufunhub.com/.well-known/assetlinks.json
```

If the fingerprints do not match the installed build, Android shows the
Chrome address bar again.

## Play Store checklist

1. Create the app in Play Console (Google Play developer account).
2. Upload `dist/edufunhub.aab` to Internal testing and opt in to Play App Signing.
3. Add the Play App Signing SHA-256 to `ANDROID_SHA256_CERT_FINGERPRINTS`.
4. Store listing: icon `store_icon.png` (512), feature graphic 1024x500,
   phone screenshots, privacy policy `https://edufunhub.com/privacy`.
5. App content: target audience (includes children, so Families policy
   applies), data safety, content rating, ads declaration (sponsor ads exist).
